Terra's positioning, verbatim: "A fast, efficient model for visual reasoning, precise computer use,
and clear, natural writing." Only snapshot: `gpt-6.1-terra` (no dated snapshot). Endpoints: Chat
Completions, Responses, Batch.

What this means for the app's request shape (`OpenAIChatProvider.swift`):

- Grounded turns already go through the Responses API (`options.useGrounding && route == .openAI`),
  which is where Terra's `web_search` lives.
- `/think minimal` maps to `none`. Terra accepts `none`, which is exactly where `gpt-6.1-sol` failed
  (HTTP 400, `2026-10-03-audit.md`).
- `.default` sends `low` to every `gpt-6*` slug (`reasoningEffort`, prefix check), so Terra gets
  the same short-latency default as Sol and Luna without new code.

## Pareto check

**Terra is a frontier point, so it was missing.** Nothing we ship dominates it:

- Luna is cheaper but sits on the nano rung.
- Sol costs 2× on both axes.
- 5.4-mini is cheaper, but has 400k context against Terra's 1.05M, and a knowledge cutoff ten
  months older.

**Terra does not dominate gpt-5.4-mini, so mini stays.** Domination needs Terra to tie or win on
every axis. It loses on both price axes:

- input $1.00 vs $0.75 (+33 %)
- output $5.00 vs $4.50 (+11 %)

Terra wins on:

- context: 1.05M vs 400k
- knowledge cutoff: 2026-06 vs 2025-08
- generation, and a wider effort range

Quality and latency between the two are **unmeasured**. The rule leaves room for "nearly the same
price and clearly better", but it needs a measurement to say "clearly better", and there is none.
So no `chatReplacement` on mini today.

Research-not-coding rule (owner, 2026-09-29): Terra fits it better than mini. It has a fresher
cutoff for research questions and 1M context for long pasted sources, at a moderate price. It is
not a coding flagship (that would be `gpt-6-astra`, still excluded).

**Default unchanged.** `ChatModelProvider.openai.defaultChatModel` stays `gpt-6-sol`. Terra is
unmeasured, and a default switch needs the probe below first.

## Open: the live probe (needs an OpenAI key)

This session had no `OPENAI_API_KEY` in its environment, so nothing below was measured. Run it on
the Mac before the next release, the same way `gpt-6.1-sol` was probed in `2026-10-03-audit.md`:

1. `bash scripts/test-openai-models.sh` must show `gpt-6.1-terra` 200 on chat completions.
2. Send `reasoning_effort: "none"` on chat completions. Expect 200. A 400 means `/think minimal`
   breaks, and Terra must then map minimal → low, the way the Sol note describes.
3. Send Responses + `tools: [{type: "web_search"}]`. Expect 200 with citations.
4. Latency: 6 interleaved, shuffled rounds against `gpt-6-sol` and `gpt-5.4-mini`, chat
   completions, default effort (the app sends `low`), with short research questions. The
   reference is Sol's median of ~1.9 s.

How each result changes the decision:

- Terra median ≤ Sol's and the answers are fine → propose Terra as the OpenAI chat default (half
  Sol's price). That needs the owner's word, because it moves new users.
- Terra ≤ mini's latency and quality clearly better → the owner may set
  `openaiGPT5Mini.chatReplacement = .openaiGPT61Terra`. +33 % input for 2.6× context and a fresher
  cutoff. Keep the enum case: `speakerConsolidationModel` uses mini.
- Terra rejects `none`, or is markedly slower than Sol → keep it as an opt-in rung and note the
  mapping.
