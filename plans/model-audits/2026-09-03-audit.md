### `gemini-3.5-transcribe` — measured this session *(probe)*

Not in the benchmark, so I ran the same fixtures, the same scoring, and the app's real
prompt + 17-term glossary (from `build/benchmark-fixtures/system-prompts-snapshot.md`, refreshed
06:13 today by the benchmark itself):

| | Result |
|---|---|
| Silence leaks | **0/9 — every run returned literally zero bytes of content** |
| Glossary | 27/51 terms (**53%**) |
| Latency (indicative) | 1228 ms @1.3 s · 992 ms @8.2 s · 1171 ms @21.3 s, n=5 each |

Two caveats on those numbers. The latency figures come from a **single-model sequential loop**,
not the interleaved protocol — the benchmark's own docstring warns that sequential loops produced
2× differences that did not replicate, so treat them as "same ballpark", not as a ranking.
And the response shape differs: the transcript arrives as
`candidates[0].content.parts[0].audioTranscription.text`, **not** `parts[].text`. The app's Gemini
decoder would return empty for every request until a branch is added — this is not a pure enum
change.

What it means: **this is the first Gemini transcription model that does not fabricate on silence.**
Every Flash tier we ship leaks (3/9 at best, 9/9 at worst); this one is 0/9, matching
`gpt-transcribe` and `grok-stt`. Its cost is Gemini-competitive (~$0.005/min all-in vs
`gpt-transcribe` $0.0045/min). Its weakness is glossary: 53% vs the current default's 71%.
