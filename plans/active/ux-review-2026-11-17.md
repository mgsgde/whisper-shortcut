## Specs (from the consult, for the build)

**A. Try-it step.** Title "Try it". Subtitle by start key — Fn: "Press 🌐, read the sentence aloud,
then press 🌐 again."; shortcut: "Press {keys} together, read the sentence aloud, then press them
again." (`DictationOnlyKeyNames.spell`). Under the sentence card a `TextEditor` (max width 580, height
96, `.title3`, `cardChrome()`, padding 12, placeholder "Your text appears here.", focused on appear and
on recording start). Caption row "Key not working?" + plain button "Use a button instead" → today's
`OnboardingTryItPanel`. `onSuccess` when the editor turns non-empty after a dictation; no success UI,
Continue turning prominent is the signal. No start key / Fn without Accessibility → show the button
panel directly. Empty result → inline caption "(no speech detected)". German: "Lieber per Klick testen";
subtitle wraps to two lines (`fixedSize(vertical)`).

**B. Recorder control.** Button ≥160×28 pt, radius 6, `controlBackgroundColor`; keycap chips 20×20,
radius 4, 13 pt medium system font, 4 pt gap. States: set (chips, ✕ on hover), empty ("Click to
record"), recording (2 pt accent ring, "Type shortcut…", Esc cancels, Delete clears), conflict (keep
Reassign/Cancel). Section subtitle "Work from any app. Press once to start, again to stop." Fn row
"Also start with 🌐 Fn" indented under Dictate. German: "Zum Aufnehmen klicken", "Kurzbefehl
eingeben…", "Auch mit 🌐 Fn starten".
